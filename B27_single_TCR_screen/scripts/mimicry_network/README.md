# Workflow 2 — `mimicry_network` (TCR59 / TCR63 published figures)

The two published **mimicry-network figures** of the TCR59 / TCR63 HLA-B\*27:05 screens,
plus the interactive label editor they were annotated with:

- `tcr59_mimicry_red_d3_gene.{pdf,svg,eps,png}` — TCR59, 6.5 × 5.2 in, with
  Edges/Nodes legend
- `tcr63_mimicry_red_d3_gene.{pdf,svg,eps,png}` — TCR63, same format
- `label_editor.html` — self-contained interactive viewer/editor of both networks,
  opened directly in a browser; shows the current hand-adjusted label state

## Network definition

- **Nodes**: peptides with `add_flow_single_copy > 5` in the flow-validated results
  (`data/results/*_add_flow.csv`, produced by `peptide_screen` + flow validation)
- **Edges**: amino-acid Levenshtein distance `d ≤ 4` (render threshold `dispTh` from
  `tcr5963_layout_TCR59.json`); cluster colors from average-linkage hierarchical
  clustering on Levenshtein distance (`cut = 6.0`, tab20 palette)
- **Red edges = mimicry edges**: cross-origin (virus ↔ human self) pairs with `d ≤ 3`;
  line width decays with `d`. All remaining edges (same-origin, or cross-origin `d = 4`)
  are drawn light gray and heavily weakened
- **Node shape** = origin (virus = circle, human self = triangle); participant node
  outlines colored by origin (virus #d32f2f / human self #1565c0, 1.0 pt)
- **Labels**: every mimicry participant is annotated (no gene-name deduplication);
  two-line gene edition — peptide sequence on top, gene name below; virus gene names
  use current UniProt entry names (looked up by fasta accession in
  `uniprot_virus_current.json`, batch-checked 2026-09), self peptides use the `Gene`
  field; every label carries a dark-red dashed leader line (#a85757, dash 3-2)
- The nogene label set (sequence-only) is computed too — it feeds the editor's
  "Sequence only" view; figures are only saved for the gene edition

## Scripts

| Script | Role |
|---|---|
| `plot_mimicry_red.py` | renders the two gene figures and exports `{tcr}_labelpos_d3.json` (exact node/edge/label positions) as input for the drag editor; hand-adjusted positions from `labelpos_override_d3.json` win when present |
| `gen_label_editor.py` | rebuilds `label_editor.html` from the position exports |

## Label editing workflow

1. `python scripts/mimicry_network/plot_mimicry_red.py` — renders the figures and
   writes `figures/mimicry_network/{tcr}_labelpos_d3.json`
2. `python scripts/mimicry_network/gen_label_editor.py` — writes `label_editor.html`;
   open it in a browser
3. Drag a label to move it; double-click a label to flip its anchored edge;
   drag empty space to pan, wheel to zoom
4. **Export override JSON** → save as `data/mimicry_network/labelpos_override_d3.json`
5. Rerun both scripts — override positions win; the committed
   `labelpos_override_d3.json` (55 labels) reproduces the published figures

## Run

```bash
conda activate b27-tcr-screen
python scripts/mimicry_network/plot_mimicry_red.py    # the two figures
python scripts/mimicry_network/gen_label_editor.py    # label_editor.html
```

**Reproducibility**: the committed PNGs are byte-identical to the published figures
(MD5-verified). Regenerated SVG/EPS/PDF have identical geometry; only randomly generated
element IDs and creation-date metadata differ between runs.

## Figures (`figures/mimicry_network/`)

- the two figures × 4 formats (PDF / SVG / EPS / PNG) + `*_labelboxes.json`
  label-placement audits (label text, box center, clearance)
- `{tcr59,tcr63}_labelpos_d3.json` — exact node/edge/label positions; the committed
  input of `gen_label_editor.py`
- `label_editor.html` — the interactive editor (regenerated by `gen_label_editor.py`)

## Provenance

The committed layouts were produced by an interactive force-directed bench whose
tuning parameters are recorded in `tcr5963_layout_TCR59.json`. A journal-assembly
small-panel edition (`plot_mimicry_small.py`, square-aspect TCR59 `round` layout via
`relayout_tcr59_round.py`) and the sequence-only figure edition were part of the
working chain; those scripts and their inputs are preserved in the repository history
(commit `a8f3f1d`) and can be restored from there if needed.
